更新时间：2026-08-06（Asia/Shanghai）

## 1. 归档口径

- 只把比赛平台返回的 `Case1`～`Case5` 和 `prof_sum` 记为官方成绩。
- 五个 Case 必须全部 `Pass`；本地正确性、NPU Event、公开 shape A/B 和
  `msprof` 试验矩阵均不能代替官方成绩。
- `Δ前次` 为本次 `prof_sum -` 上一个有官方结果版本的 `prof_sum`；负数表示
  变快，正数表示变慢。
- S02AY、S02BD、S02CE、S02CG 等虽形成过包或云端实验，但没有收到完整的
  官方五 Case 成绩，因此不混入成绩排名表。
- 隐藏 shape、dtype 和 TilingKey 未公开，不根据成绩反推或硬编码测试数据。

## 3. 关键结论

1. 全部历史官方记录中，最低 `prof_sum` 是 **S02F 的 3223.995 μs**。
2. S02BA 之后代码分支的最低观测是 **S02CA 的 3982.569 μs**，但它仍比
   S02F 慢 `758.574 μs`。因此“当前源码分支最好”和“全部历史成绩最好”
   必须分开表述。
3. 2026-07-30 记录的第 10 名为 `1268.598 μs`。即使以历史最好 S02F
   计算，仍需下降 `1955.397 μs（60.65%）` 才能达到该门槛。
4. S02BA 之后多次公开 A/B 获得数倍乃至数十倍局部加速，但官方总分长期
   停留在约 `3982～4013 μs`，说明旧性能矩阵和官方评分路径不等价。
5. S02CN 后已停止继续依赖旧 Event 图谱，改用题面合法范围、三种 dtype、
   官方式30轮任务流和 S02CA→候选→S02CA 的 `msprof` A/B/A 门禁。

## 5. 后续追加规则

每次平台返回结果后，在本表末尾新增一行，至少记录：

```text
版本号 / 提交日期 / ZIP SHA-256 / Case1～Case5 / prof_sum /
相对前次变化 / 相对历史最好变化 / 是否晋级 / 对应报告
```

若出现 `Run failed`、`Incorrect op name` 或任一 Case 未通过，应照常归档，
但标记为“正确性失败”，不得填写或比较不完整的 `prof_sum`。
